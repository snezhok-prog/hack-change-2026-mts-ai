# Проверка локального веба для жюри

## Запуск

1. В корне репозитория создайте `data` и положите туда предоставленный организаторами
   `knowledge-base.zip`. Не публикуйте его в git.
2. Создайте локальный `.env` по `.env.example`: адрес, ключ и идентификатор разрешённой
   модели, отдельный случайный `ADMIN_TOKEN`. Конкурсный ключ выдаётся только внутри
   платформы, для веба нужен отдельный доступ. Не помещайте ключ в URL или скриншот.
3. Выполните `docker compose up --build`. Compose читает `.env`; обычный Python сам
   этот файл не загружает. Откройте http://127.0.0.1:8000/ на той же машине.
4. `/api/health`: `ready`, `knowledge_base_ready`, `model_configured` должны быть true.
   `provider_verified` становится true только после успешного ответа в этом процессе.

## Сценарий

- Задайте вопрос: «Нам нужен автоматический сбор показаний на трёх складах.
  Какие исходные данные подготовить для обсуждения?»
- Дождитесь ответа. Включите «Источники и время» для проверки фактических оснований.
  Оцените ответ по сути: HTTP200 сам по себе не подтверждает достоверность.
- Заполните только выдуманные ФИО, телефон и компанию. Подтвердите тестовые контакты
  и нажмите «Сохранить заявку». Должно появиться подтверждение сохранения в прототипе
  и резюме. Отправки в МТС или CRM нет.
- «История для проверки» открывается с локальным `ADMIN_TOKEN`; не демонстрируйте ключ
  зрителям. Кнопка «Новый диалог» очищает текущий интерфейс, прошлый диалог остаётся в архиве.
- При остановке сохраняйте volume `session-data`: не используйте `docker compose down -v`.

## Границы демонстрации

- После пятой попытки Docker обновлён до `a6e1501`: health ready=true, контейнер
  healthy, интерфейс доступен. Суточная бесплатная API-квота исчерпана; повторный
  живой E2E на этом ядре не выполнен, provider_verified=false. Перед показом нужен
  успешный ответ после восстановления квоты; наличие настроек не подтверждает доступ.
- Прототип слушает только localhost; это не адрес удалённого доступа для жюри.
- Реальная CRM не подключена. Для внедрения потребуется согласованная интеграция,
  защита публичного доступа, политика персональных данных и пилот на реальных задачах.
- Эффект на конверсию, экономию клиента и время менеджера пока не измерен.
- Конкурсный code-only ZIP предназначен для автоматической оценки. Финальный комплект
  дополнительно требует актуальные документы и PDF-презентацию по правилам кейса.
