# Независимый аудит поиска и переданного контекста

Проверено на `c94b95b6c88368b874fbc390a9fae58c33234fb5`. Данные полностью синтетические.
Скрипт не обращается к сети, не требует API, базы МТС или ключей.

Из корня репозитория с установленными requirements.txt:

```sh
python docs/reviews/reproduce-retrieval-findings.py
```

## Результаты и критерии исправления

| Проверка | Фактический результат | Требуемое поведение |
|---|---|---|
| «Расходы растут. Как разобраться в счёте?» | named_products возвращает платформу учёта | Продукт не назван; пустое множество |
| «Нам не нужна СЭС. Интересует выход на оптовый рынок.» | Приоритет и solar, и ОРЭМ | Отклонённая СЭС не получает boost |
| «Распознавание по фото не подходит. Нужен автоматический сбор.» | Приоритет PHOTO и платформы | Отклонённый PHOTO не получает boost |
| Условие в конце защитного раздела длиной 2792 символа | В material отсутствует, в debug sources присутствует | Сохранить условие и показывать фактически переданный контекст |

Причины:
- В QUERY_SYNONYMS аббревиатура `асту` не ограничена границами слова и совпадает с «растут».
- named_products собирает все совпадения без учёта отрицаний или изменения намерения.
- split_document допускает 2800 символов в chunk, но автоматически добавленный guard
  ограничивается срезом 2500. sources сохраняет полный исходный chunk.
  Воспроизведение использует 2792 символа, то есть допустимый размер chunk.

## Проверка исправления

1. Ограничить аббревиатуры границами; проверить реальные аббревиатуры и обычные слова.
2. Учитывать явный отказ от продукта и последнюю цель. Не удалять любое совпадение
   рядом с «не»: «не получается настроить СЭС» не означает отказ от продукта.
   Сохранить поддержку сравнения двух продуктов.
3. Сохранять полный смысл защитных условий при формировании material.
   Проверять итоговый текст запроса, а не только имена документов и sources.
   Если текст действительно сокращён, debug должен показывать именно переданный фрагмент.
4. Повторить официальный набор локально и отдельно сравнить генерацию на той же модели.

Эти проверки воспроизводят ошибки признаков поиска и сборки контекста, а не измеряют
конкурсное качество. Они не доказывают причину конкретного ответа C-017 и не обещают
прирост public-score. Для C-017 требуется проверить фактический material того запуска
без публикации базы. Обсуждение: issue #5, G-020.

Изменения ядра выполняет его владелец. Этот PR добавляет только протокол и офлайн-скрипт.
