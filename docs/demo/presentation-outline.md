# Презентация EnergyTool — структура на 8 слайдов

Владелец: popt-web. Задача: #3. Приоритет: P0.
Статус: текстовая структура; PDF и визуальные материалы ещё не подготовлены.
Оценка оформления: 2–3 часа после репетиции и получения разрешённых кадров.
Основание: код main e3e04d7b1e8731482651c7f00398f3c9ba033792 и документы на 09.11.2026.
Сценарий и критерии проверки: [scenario.md](scenario.md).

## 1. Задача и решение — 20 секунд

**Заголовок:** EnergyTool: от бизнес-вопроса к заявке с контекстом.

Клиент описывает задачу; консультант ищет подходящие материалы, уточняет ситуацию
и помогает перейти к разговору со специалистом.

На первом слайде разместить кликабельную ссылку:
https://github.com/snezhok-prog/hack-change-2026-mts-ai

Подпись: Hack&Change 2026 · кейс МТС · прототип команды.
Визуал: собственная схема «Вопрос → консультация → тестовая заявка».
Не использовать неподтверждённые показатели экономии, конверсии и качества.

## 2. Пользовательский путь — 25 секунд

1. Описать задачу своими словами.
2. Уточнить исходные данные.
3. Получить ответ на основе найденных материалов.
4. По желанию заполнить форму с выдуманными контактами.
5. Увидеть локально сохранённую заявку и резюме.

Визуал: собственная схема или разрешённый обезличенный кадр S1.
Оговорка: контакты вводятся в отдельной форме; пошаговый сбор внутри чата
не реализован как отдельная детерминированная логика.

## 3. Архитектура — 30 секунд

**Одна логика консультации, два способа использования.**

- База Markdown в ZIP → секции → BM25 → контекст → API модели.
- Общее ядро: retrieval.py, model_client.py, consultant.py.
- Batch: solution.py → submission.csv; корневые файлы упаковываются для платформы.
- Web: FastAPI → SQLite; интерфейс HTML/CSS/JS.
- Docker Compose для локального запуска.

Визуал: собственная схема с двумя ветвями batch/web.
Не изображать bge-m3, реранкер, CRM или React как уже работающие части.
В docs/AI-CORE.md они могут встречаться как план; ориентироваться на текущий код.

## 4. Обоснованность ответов и границы — 30 секунд

Системный промпт ограничивает продуктовые факты переданными фрагментами.
Источники и время доступны в режиме отладки. При отсутствии сведений промпт
требует честно сообщить об ограничении и предложить специалиста.
Отказ от телефона не должен блокировать консультацию.

Оговорка: промпт и найденные фрагменты не гарантируют отсутствие галлюцинаций;
фактическую обоснованность проверяют на вопросах и реальных ответах.
Источники в debug — найденные кандидаты, а не доказательство проверки каждого факта.

Визуал: собственная схема, без текста закрытой базы.

## 6. Демонстрация — 60–90 секунд

Короткая версия [сценария](scenario.md):
задача трёх складов → уточнение → ответ → тестовая заявка → новый диалог → архив.
Полная версия занимает 3–5 минут и используется отдельно при достаточном времени.

Визуал: живой локальный интерфейс либо разрешённая запись реального прогона.
Если используется запись, явно обозначить её как запись и указать версию.
Если API недоступен, показать ошибку и ограничения; не подменять консультацию
заготовленным ответом. Закрытые материалы в публичную запись не включать.

## 7. Надёжность и ограничения — 30 секунд

Реализованы изоляция сессий, постоянная история в SQLite, обработка API-ошибок,
тестовые заявки без внешней отправки, ключ доступа к списку архива.
Секреты настраиваются через окружение, материалы организаторов в git не входят.

Текущие пределы: localhost-демо, один процесс приложения, обязательна отдельная
защита перед публичным размещением; семантический поиск и реранкер ещё в плане.
Архив показывает последние 100 сессий. Резюме заявки сейчас составляется
из сообщений клиента и последнего ответа, без отдельной LLM-суммаризации.

## 8. Ближайшие шаги — 20 секунд

1. Реальный прогон на демонстрационных вопросах и измерение качества/времени.
2. Проверка временного бюджета и отправка ZIP на платформу.
3. Репетиция веб-сценария, разрешённые кадры, финальный PDF.

Официальные сроки и комплект сдачи сверить по платформе.
Во входной сводке указаны 15.11.2026 как внутренний дедлайн и 16.11.2026 как основной;
точное время не подтверждено.

Завершающая фраза: «Прототип объединяет консультацию, проверяемые источники
и локальную заявку; качество модели и конкурсный результат подтверждаем отдельно».

## Контроль перед экспортом PDF

- Ссылка на репозиторий есть на первом слайде и работает после экспорта.
- Ни на одном слайде нет ключей, реальных контактов, закрытой базы или сырых ответов API.
- Для каждого численного результата есть конкретный прогон и условия измерения.
- Реализованные возможности отделены от плана.
- Кадры соответствуют демонстрируемой версии, разрешены к показу и читаемы.
- Нет утверждений об отправке в CRM/МТС, принятом сабмите или балле без подтверждения.
- PDF открывается, шрифты читаемы; финальный набор проверен по регламенту организаторов.
