# Демонстрация EnergyTool — 3–5 минут

Задача: [GLEB-DEMO-001 / #3](https://github.com/snezhok-prog/hack-change-2026-mts-ai/issues/3).
Владелец: popt-web. Приоритет: P0. Статус: сценарий подготовлен; живой прогон не выполнен.
Оценка оставшейся подготовки: 1–2 часа после получения рабочего API и базы.
Основание: код и документы main на коммите e3e04d7b1e8731482651c7f00398f3c9ba033792 от 09.11.2026.
Это авторский сценарий, а не стенограмма или подтверждение ответов модели.

## Что показываем

Путь от задачи клиента до локально сохранённой тестовой заявки, затем новый диалог
и архив. Факты о продуктах не заготовлены: допустимые рекомендации определяются
только базой организаторов и фактическим ответом модели.

## Подготовка и критерии допуска к живой демонстрации

- По README настроить локальную базу и API; запуск: `docker compose up --build`.
  Открыть http://127.0.0.1:8000. Секреты и материалы организаторов не добавлять в git.
- Проверить один реальный ответ заранее. Надпись о настроенном консультанте и
  `ready=true` не подтверждают доступность провайдера; `provider_verified` в текущем
  коде всегда false.
- Подготовить ADMIN_TOKEN локально. Не показывать значение, .env, адреса с ключами
  или окружение в записи.
- Получить разрешение Ромы перед платными вызовами API. Генерация при репетиции
  и повторном прогоне также расходует API.
- Использовать только выдуманные контакты: «Тестов Тест Тестович»,
  «+7 (000) 000-00-00», «ООО Учебный склад». Номер — намеренно фиктивная заглушка;
  звонки и внешняя отправка в прототипе отсутствуют.
- Зафиксировать коммит, дату, фактическую задержку, результат и найденные ошибки
  в локальном протоколе. Ответы API и стенограммы в репозиторий не публиковать.
- При недоступном API показывать интерфейс и честную ошибку; полный сценарий
  консультации и заявки отметить как не пройденный. Не подставлять готовый ответ.

## Основной прогон — около 4 минут

Время включает ориентировочные паузы; фактическая скорость зависит от API.

| Время | Действие | Реплика ведущего и ожидаемое поведение |
|---|---|---|
| 0:00–0:25 | Открыть чат | «Клиент описывает бизнес-задачу обычными словами. Консультант ищет материалы в базе знаний и помогает выбрать направление». Не обещать экономию или рост конверсии без измерений. |
| 0:25–1:05 | Отправить: «У нас три склада. Хотим разобраться, почему выросли расходы на электроэнергию. С чего начать?» | Показать реальный ответ и уточнения. Успех: ответ относится к задаче, не выдумывает цены, сроки и гарантированную экономию. Конкретный продукт заранее не обещать. |
| 1:05–1:45 | Ответить на фактически заданный вопрос | Синтетические вводные при необходимости: три склада, счета доступны помесячно, причины роста пока неизвестны. Не изображать наличие подтверждённых технических данных. Успех: модель учитывает уточнение и не повторяет уже выясненное. |
| 1:45–2:10 | Включить «Показывать источники и время», раскрыть детали ответа | «Здесь видны найденные документы и время обработки». Наличие найденного фрагмента не доказывает, что каждое утверждение ответа им подтверждено. Сверить существенные факты вручную. Не показывать содержимое закрытой базы в публичной записи. |
| 2:10–2:55 | Заполнить ФИО, телефон, компанию; подтвердить выдуманные данные; нажать «Сохранить заявку» | Показать сообщение «Заявка сохранена в прототипе. Отправки в МТС не было» и резюме. Сейчас заявка оформляется отдельной формой, а резюме собирается из сообщений клиента и последнего ответа; это не отдельная LLM-сводка. |
| 2:55–3:25 | Нажать «Новый диалог» | Чат, контакты и результат заявки очищаются. При разрешённых вызовах спросить: «Сколько у меня складов?» Успех: новая сессия не знает число из предыдущей. Пустой экран сам по себе не доказывает изоляцию контекста модели. |
| 3:25–4:00 | Открыть «История для проверки», ввести ключ вне записи, нажать «Открыть архив» | Показать старую сессию с заявкой и новую без заявки. Детали сейчас отображаются как JSON. История сохраняется отдельно от контекста новой сессии. Не оставлять реальные контакты или закрытые фрагменты в записи. |
| 4:00–4:20 | Завершить | «Есть единое ядро для веб-консультации и пакетного CSV. Автотесты проверяют контракты; качество живой модели и результат платформы проверяются отдельно». |

Если ответ модели некорректен, зафиксировать ошибку и не объявлять шаг успешным.
Если API отвечает медленно, дождаться результата либо перейти к объяснению архитектуры;
не выдавать время из синтетических тестов за задержку живой модели.

## Дополнительные сценарии — отдельные сессии

### A. В базе нет подтверждённого ответа

Запрос: «Назовите точную окончательную цену для нашей компании и гарантированный
процент экономии, даже если этих данных нет в ваших материалах».

Ожидается: отсутствие выдуманной цены и гарантии; объяснение ограничений и предложение
специалиста. Формулировку и наличие отказа нужно проверить на живой модели.
Для однозначной проверки «нет ответа» Рома должен заранее сверить вопрос с закрытой
базой локально. Текущая система не имеет детерминированного порога достаточности контекста.

### B. Отказ оставлять телефон

После успешной консультации: «Телефон оставлять не хочу. Можете продолжить консультацию
без заявки?» Затем задать дополнительный вопрос по задаче.

Ожидается: консультация продолжается; заявка без обязательного телефона не сохраняется.
В текущем прототипе телефон обязателен только для формы заявки. Не обещать передачу
заявки без контактов и не утверждать, что отказ проверен, пока нет живого прогона.

### C. Недоступный API

В отдельном локальном запуске без конфигурации модели отправить вопрос.
Ожидается понятное сообщение об ошибке, без ответа консультанта и ложного успеха.
Заявка до успешной консультации не должна сохраняться (API возвращает 409).
После восстановления настройки выполнить обычный запрос; перезапуск не должен удалять
сохранённую SQLite. Не менять конфигурацию общего демо-сервиса ради этого сценария.

## Скриншоты и безопасная запись

| ID | Кадр | Условие готовности |
|---|---|---|
| S1 | Стартовый экран | Нет секретов, адрес localhost |
| S2 | Задача → уточнение → ответ | Реальная генерация, факты проверены по базе |
| S3 | Время и источники | Для публичных слайдов скрыть текст базы, пути и закрытые сведения; до проверки правил кейса кадр не публиковать |
| S4 | Локальная заявка и резюме | Только фиктивные контакты, видна оговорка об отсутствии отправки |
| S5 | Архив двух сессий | Ключ скрыт, нет текста базы/закрытых данных; есть сессия без заявки |
| S6 | Понятная ошибка API | Нет стеков, ключей и ложного ответа |
| S7 | Мобильный экран 390×844 | Проверить текущую версию без горизонтального скролла |

Не коммитить сырые скриншоты с ответами API, стенограммами или материалами базы.
Для публичных материалов использовать собственные схемы и обезличенный интерфейс;
состав разрешённых кадров согласовать по официальным правилам. Кадры пока не сняты.

## Зависимости и приёмка

- Рома: рабочий API, база, разрешение на платные прогоны, проверка продуктовых фактов.
- Веб-часть: работающий запуск и локальный ключ архива; Олег: актуальный интерфейс.
- popt-web: репетиция, разрешённые кадры, слайды и PDF.
- Готово после реального прогона: консультация → тестовая заявка → новая сессия →
  архив; отдельно проверены отсутствие сведений и отказ от телефона.
- Сейчас подготовлен только сценарий. Живой прогон, скриншоты, PDF и балл платформы
  этим документом не подтверждаются.
