# Архитектура первой итерации

Владельцы модулей — в [AGENTS.md](../AGENTS.md). ИИ-ядро (`retrieval`, `consultant`, `model_client`, `solution`) ведёт Рома; план его развития — [AI-CORE.md](AI-CORE.md).

- `retrieval.py`: безопасное чтение ZIP без распаковки, секции Markdown. Поиск в три ступени: BM25 по разделам (с расширением запроса синонимами клиента — «АСКУЭ», «СЭС», «воруют» → формулировки базы — и приоритетом продукта, который клиент назвал сам) → смысловой поиск bge-m3, слияние RRF → реранкер Qwen3, если задан. Любой сбой эмбеддера или реранкера откатывает на предыдущую ступень. Запрос строится только из реплик пользователя.
- `model_client.py`: OpenAI-совместимый клиент `/chat/completions`, `/embeddings`, `/rerank`; настройки из env с терпимостью к заглушкам; максимум три попытки генерации; общий дедлайн отменяет зависший запрос; вырезание `<think>` и отключение рассуждений Qwen3 с откатом, если прокси не принимает параметр. Обрыв по `finish_reason=length` допускает одно увеличение бюджета токенов при наличии следующей попытки. Невосстановленный обрыв завершается ошибкой: отрезать окончание небезопасно, потому что там может находиться условие цены или обещания.
- `consultant.py`: общее stateless-ядро для сабмита и веба. Контекст — найденные разделы плюс «Факты, которые можно утверждать» / «Чего утверждать нельзя» для каждого найденного продукта. Промпт: прямой ответ → факты → один уточняющий вопрос; цифры только своего продукта, без собственных расчётов; вне компетенции — отказ и специалист. Пост-обработка убирает ссылки `[n]` и Markdown. Промпт ограничивает факты базой, но это не доказательство отсутствия галлюцинаций.
- `solution.py`: контракт CSV платформы. Полный файл с честными запасными ответами пишется сразу, затем по ходу прогона заменяется реальными ответами (промежуточные сохранения); ошибка вопроса, базы или модели не обрывает прогон; ID возвращаются как во входе. Эти четыре модуля и `requirements.txt` нужны платформе в корне ZIP.
- `eval.py` (только разработка): локальный LLM-судья по схеме организаторов — два раунда со сменой порядка, Match Rate / Win Rate, A/B версий.
- `web.py`, `storage.py`: FastAPI, SQLite, изолированные сессии, постоянная история, заявка и краткое содержание. Один процесс Uvicorn.
- `static/`: HTML/CSS/JS без сборщика. Данные отображаются через textContent. В начальной реализации React не требуется.

После исходных фрагментов и полных ограничений `Consultant.context` добавляет недостающие
промежуточные родительские разделы, затем дополнительные разделы ведущего найденного
документа. Все chunks одного родителя добавляются вместе либо пропускаются целиком.
Лимит дополнений — 4000 символов, общий предел — 14000 с форматированием; уже имеющиеся
исходные фрагменты и ограничения не обрезаются. Новые документы этим расширением
не вводятся. Если embeddings недоступны, настроенный reranker продолжает работать
с лексическими кандидатами. Наличие этих этапов не доказывает их фактическое включение
в скрытом окружении платформы.

## HTTP-контракт для frontend

| Метод и путь | Вход | Результат |
|---|---|---|
| GET `/api/health` | — | ready, mode, provider_verified, knowledge_base_ready, model_configured, model |
| POST `/api/sessions` | — | 201: id |
| GET `/api/sessions/{id}` | — | id, created_at, messages, lead |
| POST `/api/sessions/{id}/messages` | text | answer, sources, elapsed_ms |
| POST `/api/sessions/{id}/lead` | name, phone, company, test_data_confirmed | 201: сохранённая заявка |
| GET `/api/admin/sessions` | Authorization: Bearer ADMIN_TOKEN | последние 100 диалогов, включая без заявки |

Ожидаемые ошибки: 401 — архив без ключа; 404 — неизвестная сессия; 409 — заявка до консультации или изменение уже сохранённых контактов; 422 — валидация; 429 — заняты слоты; 503 — модель не настроена/недоступна. В ошибке поле detail. Повтор идентичной заявки возвращает тот же id.

`knowledge_base_ready` сообщает об успешной загрузке базы независимо от настроек API. `model_configured` означает валидную конфигурацию, а не проверенный сетевой доступ. `model` содержит только идентификатор настроенной модели/маршрута или null; ключ и адрес API не выдаются. `provider_verified` становится true после первого успешного ответа через настроенный клиент в текущем процессе и сбрасывается при перезапуске; это не оценка качества и не гарантия следующего ответа. Ошибка 503 при отсутствии конфигурации называет конкретный недостающий компонент.

Каждая загрузка страницы создаёт новый контекст. История остаётся в SQLite. ID сессии — случайный секрет доступа к её содержимому; текущая версия предназначена для localhost и тестовых данных, не для публичного продакшена.
